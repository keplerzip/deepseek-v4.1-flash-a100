以下为操作者回传的隔离目标机结果。原始逐请求 JSONL 未传到构建工作区。见 [机器可读记录](../reports/dspark-k5-k7.user-reported.json)、[测试实现](../deploy/tests/dspark_benchmark.py)。

|---|---:|---:|---:|---:|---:|
| off | 5 | 139.80 | 137.22 | 1379.01 | 24.56 |
| off | 7 | 146.04 | 143.50 | 1359.60 | 25.28 |

原报告百分比：off k7 单流 +4.46%、C32 −1.41%；high 单流 −12.97%、C32 −7.61%。表格数值舍入为两位小数，重新计算百分比可能略有差异。默认据此选择 k5；k7 功能通过不代表更快。

## 方法

- 同模型、同机器、TP8、256K 配置、两组均 Engram 主存卸载。
- 固定顺序 5→7；off/high 分开。每组 2 次预热、5 次单流、200 个 C32 请求，每请求要求 1024 输出 token。
- 对照工具校验请求 SHA256、输入/输出/命中 token 一致性，保存逐请求计时与 SSE 摘要。
- decode 使用 `(completion_tokens-1)/(最后一个含 token 事件时间-第一个含 token 事件时间)`。DSpark 一次事件可能输出多个 token，因此事件间隔不是逐 token 延迟。
- C32 总吞吐为完成输出 token / 负载墙钟时间；P95 为请求端到端延迟。high TPS 包含思考 token。

五个样本与固定顺序不足以给小幅差异作统计显著性结论。此实验不能隔离 Engram 成本，也不能证明相对旧模型的固有速度变化。C32 短输入不等于 C32 满 256K 驻留。
